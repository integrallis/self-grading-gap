# CLAUDE.md — verification-gap

Research repo for a peer-review paper. The predecessor project accumulated fabricated claims,
stub implementations presented as working, and results that existed only in prose. This repo is
structured so that cannot happen: the rules below are invariants, and most are mechanically
checkable.

## The one rule that generates all others

**A number that does not trace to a committed, script-generated result file does not exist.**
Not in conversation summaries, not in markdown, not in the paper. If asked "what did X score?",
the only valid sources are files under `experiments/*/results/` produced by a committed runner.

## Provenance invariants

1. Result files are written only by runner scripts. Never write or edit a results file, an
   AUDIT/ANALYSIS table, or a number in the paper by hand. Analysis markdown is generated by the
   `--stage analyze` code path from raw result files.
2. Every result file records: git SHA of the code that produced it, input file paths and their
   SHA-256, library versions, timestamps, and (for API runs) model IDs, temperatures, token
   counts, and dollar cost. A runner that cannot fill these fields is not ready to run.
3. Nothing under `experiments/*/results/` or any run log is ever gitignored. The predecessor
   gitignored `*.log` and its headline claim became unverifiable.
4. The 2025 informal-experiment materials (private archive) are **seeds, not sources**: they
   inform direction and are never cited as findings; paper numbers come only from this
   repository's fresh, instrumented runs.

## Experiment lifecycle (act-context discipline)

5. Pre-register before data: each experiment directory gets a README with hypothesis, method,
   and decision rule, committed BEFORE the first data-producing run. Amendments are allowed only
   before data collection and must be committed as such.
6. Staged runners (`--stage plan / extract / eval / analyze` as applicable); each stage refuses
   to run if its prerequisite's outputs are missing. `--limit K` smoke-tests before full runs.
7. Extraction/scoring rules are frozen in the pre-registered README. If results miss an
   expectation, the finding is the discrepancy — do not tune the extractor/scorer toward the
   expected number and re-run ("target-seeking" is fabrication with extra steps).
8. Nulls and failures are results. They are written up in the same AUDIT/ANALYSIS format and
   committed. A failed hypothesis closes a branch; that is progress.

## Measurement rules

9. Use the field-standard harness for every measurement: EvalPlus for HumanEval(+)/MBPP(+),
   official harnesses for LiveCodeBench and anything else. Writing our own test executor when a
   standard one exists is forbidden — bespoke harness bugs are how fake numbers are born.
10. Measure the noise floor before claiming a delta: repeated identical runs (N≥5) with
    confidence intervals precede any A-vs-B comparison; paired tests (McNemar / bootstrap) for
    per-problem outcomes. A delta inside the noise floor is reported as "within noise".
11. API runs record cost. Any efficiency or "cheaper model + process beats bigger model" claim
    without measured tokens/dollars for BOTH arms is forbidden.
12. LLM code generation: request markdown fenced code and parse it; never
    `with_structured_output()` for code (validated failure mode in the predecessor).

## Language rules

13. Banned without an attached statistical result: "validated", "proves", "confirms",
    "significant". Banned always: "actually/real" as emphasis, success-theater emoji tables.
14. State uncertainty as fact: "not measured", "unknown", "single run — no variance estimate".
15. When reporting to the user: if a run failed, lead with the failure and the raw error. If a
    stage was skipped, say so. No claim of completion without the output file's path.

## Git

16. Commit experiment READMEs (pre-registration) before running; commit raw results immediately
    after runs complete, before analysis or interpretation. Conventional commits. No AI
    attribution lines in commit messages.
