# Runbook — running the experiments

For team members running (and funding) experiment lanes. Everything here was executed once
already for exp006/exp007; measured costs below are from those runs, not guesses.

## 1. Keys

Create `.env` at the repo root (gitignored; never commit it):

```
OPENAI_API_KEY=...        # gpt-4o-mini (weak lanes) and gpt-5.6-terra (strong lanes)
DEEPSEEK_API_KEY=...      # only if adding a second weak-generator arm
HETZNER_TOKEN=...         # only if provisioning a runner via API (§3)
```

Runners load `.env` themselves. Every LLM call is logged with tokens and provider-computed
cost to a per-run `usage.jsonl`; every runner enforces its experiment's pre-registered budget
cap and refuses to start a new run once the cap is crossed.

## 2. Environments

```bash
uv sync                   # vgap venv: pipeline, EvalPlus scoring, analysis
uv run pytest src -q      # instrument tests (no API)
```

exp007's score stage shells out to a LiveCodeBench harness checkout (the oracle never runs
in the vgap venv):

```bash
git clone https://github.com/LiveCodeBench/LiveCodeBench ../benchmarks/LiveCodeBench
cd ../benchmarks/LiveCodeBench && uv venv --python 3.11 && uv pip install -e . \
  && uv pip install "datasets==2.21.0"   # v6 ships as a script dataset; datasets>=3 refuses it
```

The runner finds it at that sibling path by default; set `LCB_VENV_PY` to override.

## 3. Provision a runner (optional — any Linux box with Python 3.12 works)

The workload is API-bound; a small shared-vCPU instance suffices. Reference setup (Hetzner
cpx32, ~€0.01/h):

```bash
# create: Hetzner console or API (server_type=cpx32, image=ubuntu-24.04, add your SSH key)
ssh root@<ip> 'apt-get -qq update && apt-get -qq install -y rsync git tmux && \
               curl -LsSf https://astral.sh/uv/install.sh | sh -s -- -q'
rsync -a --exclude .venv --exclude __pycache__ ./ root@<ip>:/root/self-grading-gap/
scp .env root@<ip>:/root/self-grading-gap/.env
ssh root@<ip> 'cd /root/self-grading-gap && /root/.local/bin/uv sync -q && \
               /root/.local/bin/uv run pytest src -q'
```

Decommission when done — but only after syncing results back AND verifying parity
(`rsync -aqn --itemize-changes` from the box must list nothing) — then delete the server.
Lane logs (`*.launch.log` / nohup output) are part of the record: sync them too.

## 4. The experiments

Each experiment's README is its frozen pre-registration (hypotheses, decision rules, budget
cap — do not edit after data collection). Stages refuse to run before their prerequisite
exists (plan → smoke → run → score → analyze).

**exp006 — model asymmetry, HumanEval subset-30** (complete; $14.72 measured):

```bash
uv run python experiments/exp006_model_asymmetry/run_asym.py --stage plan
uv run python experiments/exp006_model_asymmetry/run_asym.py --stage smoke
for c in control_rerun strong_testgen strong_judge strong_both; do
  nohup uv run python experiments/exp006_model_asymmetry/run_asym.py --stage run --cell $c \
    > experiments/exp006_model_asymmetry/results/$c.launch.log 2>&1 &
done
uv run python experiments/exp006_model_asymmetry/run_asym.py --stage score    # EvalPlus, no API
uv run python experiments/exp006_model_asymmetry/run_asym.py --stage analyze
```

**exp007 — model asymmetry, LiveCodeBench lcb30** (complete; $37.32 measured): same shape,
`run_lcb.py`, cells `control strong_testgen strong_judge strong_both`; score stage needs the
LCB checkout from §2.

**Measured cost basis**: exp006 $14.72 and exp007 $37.32, each 4 cells × 5
runs × 30 problems = 600 problem-runs → ~$0.025 (HumanEval) and ~$0.062 (LCB, longer
statements + strong-judge feedback loops) per problem-run. Wall time: 3–8 hours for all four
cells in parallel on one box, dominated by strong-judge latency. A future full-benchmark
replication (HumanEval $n{=}164$: ~2,150 problem-runs/lane ≈ $60–130 per weak/strong lane
mix; scale LCB windows accordingly) should be pre-registered the same way before launch.

## 5. Discipline (applies to every run)

- Pre-registration is committed before the first API call; results are committed immediately
  after runs complete, before interpretation.
- Never hand-edit anything under `experiments/*/results/`; analyses are regenerated by the
  `--stage analyze` code paths.
- A failed or null outcome is a result: commit it and report it.
