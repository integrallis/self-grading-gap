## Analysis of Failing Tests

**test_mixed_id_and_here** — expected [2, 1, 1], crashes with `ValueError: invalid literal for int() with base 10: 'RE'`

Input: `numberOfUsers=3, events=[["MESSAGE", "10", "id0 HERE"]]`

The message string is "id0 HERE". The implementation takes the else branch (not 'ALL', not 'HERE'), splits on spaces to get `["id0", "HERE"]`, then tries to parse each token as `int(mentioned_id[2:])`. For "id0", it extracts "0" (correct). For "HERE", it extracts "RE" and attempts `int("RE")`, which raises ValueError.

The issue: the implementation assumes if the message is not exactly "ALL" or "HERE", then all tokens in the message are user IDs. It doesn't handle mixed messages containing keywords AND user IDs.

**test_mixed_id_and_all** — expected [1, 2, 1], crashes with `ValueError: invalid literal for int() with base 10: 'LL'`

Input: `numberOfUsers=3, events=[["MESSAGE", "10", "id1 ALL"]]`

The message string is "id1 ALL". Same issue as above: splits to `["id1", "ALL"]`, tries to parse "ALL"[2:] = "LL" as an integer, crashes.

**test_canonical_example_1** — expected [2, 2], got [1, 2]

Input: `numberOfUsers=2, events=[["MESSAGE", "10", "id1 id0"], ["OFFLINE", "11", "0"], ["MESSAGE", "71", "HERE"]]`

Trace:
- Event 1 (MESSAGE at 10, "id1 id0"): Splits to ["id1", "id0"], mentions id1 and id0. mentions = [1, 1], online_status = [True, True].
- End of event 1: timestamp=10, checks if any offline users should come back. offline_until = [0, 0], so no changes.
- Event 2 (OFFLINE at 11, user 0): online_status[0] = False, offline_until[0] = 71. mentions = [1, 1], online_status = [False, True].
- End of event 2: timestamp=11, checks if any offline users should come back. offline_until[0] = 71, but 11 < 71, so user 0 stays offline.
- Event 3 (MESSAGE at 71, "HERE"): online_status = [False, True], so only user 1 is mentioned. mentions = [1, 2].
- End of event 3: timestamp=71, checks if any offline users should come back. offline_until[0] = 71, and 71 >= 71, so online_status[0] = True.

The problem: the online status update happens AFTER processing the MESSAGE event at timestamp 71, but it should happen BEFORE. A user who comes back online at timestamp 71 should be online when a MESSAGE at timestamp 71 is processed.
