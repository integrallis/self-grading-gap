## Root cause

The implementation incorrectly assumes that each change can add 2 to the maximum distance by simply adding `min(k, len(s)) * 2` to the observed maximum. This is wrong because: (1) changes need to be strategic to extend the path in one direction, not just any change, (2) the optimal strategy requires changing moves that cancel out progress (like S after N's or W after E's), and (3) once the path is optimized, additional changes don't help. The problem requires dynamic programming or search to find which k changes maximize the furthest point reached during the walk, not a simple arithmetic formula.
