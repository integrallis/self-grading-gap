```python
from typing import List
from collections import deque


def minMaxWeight(n: int, edges: List[List[int]], threshold: int) -> int:
    # Sort edges based on their weights
    edges.sort(key=lambda x: x[2])
    left, right = 0, len(edges) - 1
    answer = -1

    while left <= right:
        mid = (left + right) // 2
        max_weight = edges[mid][2]
        graph = [[] for _ in range(n)]

        # Build graph with edges that have weights <= max_weight
        for i in range(len(edges)):
            if edges[i][2] <= max_weight:
                graph[edges[i][1]].append(edges[i][0])  # Reverse the edge direction

        # Check if all nodes can reach node 0
        if canReachZero(n, graph, threshold):
            answer = max_weight
            right = mid - 1
        else:
            left = mid + 1

    return answer


def canReachZero(n: int, graph: List[List[int]], threshold: int) -> bool:
    out_degree = [0] * n
    for u in range(n):
        out_degree[u] = len(graph[u])
        if out_degree[u] > threshold:
            return False  # Early exit if any node exceeds threshold

    visited = set()
    queue = deque([0])
    visited.add(0)

    while queue:
        u = queue.popleft()
        for v in graph[u]:
            if v not in visited:
                visited.add(v)
                queue.append(v)

    # Check if all nodes can reach node 0
    return len(visited) == n

```

### test_node_zero_has_outgoing_edges — expected 5, got -1

**Inputs:**
- n = 3
- edges = [[0, 1, 100], [1, 0, 5], [2, 0, 3]]
- threshold = 1

**Expected:** 5

**What the implementation computes:**

1. After sorting by weight, edges become: [[2, 0, 3], [1, 0, 5], [0, 1, 100]]

2. Binary search tries different max_weight values by selecting edges[mid][2]:
   - First iteration: mid = 1, max_weight = 5
   - Builds graph with edges where weight ≤ 5:
     - Edge [2, 0, 3]: graph[0].append(2) (reversed)
     - Edge [1, 0, 5]: graph[0].append(1) (reversed)
     - Edge [0, 1, 100]: skipped (weight > 5)
   - Graph becomes: graph[0] = [2, 1], graph[1] = [], graph[2] = []

3. In `canReachZero`:
   - Checks out_degree: out_degree[0] = 2, out_degree[1] = 0, out_degree[2] = 0
   - **Line `if out_degree[u] > threshold:` triggers for node 0 (out_degree[0] = 2 > 1)**
   - Returns False immediately

4. The issue is conceptual: the implementation reverses edges (making them point FROM destination TO source), then builds a graph where graph[u] contains nodes that u points to in the reversed graph. This means graph[0] contains nodes that point TO 0 in the original graph.

5. The out_degree check is counting **reversed** edges leaving each node. For node 0, it's counting how many nodes point to node 0 in the original graph (which is 2: nodes 1 and 2). But node 0 doesn't need outgoing edges to satisfy the threshold constraint — node 0 is the destination!

6. The threshold constraint should only apply to nodes that need to reach node 0 (nodes 1 through n-1), not to node 0 itself. Node 0 having multiple incoming edges is perfectly fine and shouldn't violate the threshold.

**Root cause:** The `canReachZero` function incorrectly applies the threshold constraint to node 0. Node 0 should be exempt from the out-degree threshold check because the problem asks if all nodes can reach node 0 using at most `threshold` outgoing edges **per node**. Node 0 is the target and doesn't need outgoing edges.
