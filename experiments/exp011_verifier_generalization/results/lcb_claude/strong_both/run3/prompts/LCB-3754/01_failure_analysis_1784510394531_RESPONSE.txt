## Root Cause

All three failures stem from the same algorithmic error: the implementation incorrectly calculates `max_distance_with_changes`. The formula `current_distance + min(k, count_X) + min(k, count_Y)` is fundamentally flawed because:

1. It only considers the final position, not intermediate positions
2. It incorrectly adds counts of moves as if they're distances
3. It doesn't properly model the effect of changing moves on net displacement

The correct approach needs to:
- Consider all possible ways to change up to k moves
- Track the maximum distance achieved at any point during the path after changes
- Properly compute how changing moves affects the trajectory
