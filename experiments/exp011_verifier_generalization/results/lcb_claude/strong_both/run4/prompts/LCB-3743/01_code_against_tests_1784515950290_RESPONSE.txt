## Root cause

The implementation fundamentally misunderstands the problem. It computes existing gaps and sums the k largest gaps, but the problem requires rescheduling k meetings to create one maximum contiguous gap. When you can reschedule k meetings, you can move them to pack them together (e.g., at the start or end), thereby creating a large contiguous free period. The implementation doesn't model rescheduling at all—it just looks at existing gaps.
