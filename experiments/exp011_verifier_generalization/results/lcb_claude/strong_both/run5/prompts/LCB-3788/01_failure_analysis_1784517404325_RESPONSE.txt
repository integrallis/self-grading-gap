## Root cause

All four failures share the same root cause: **the implementation uses a sliding window approach that only shrinks from the left when duplicates are encountered, but never considers starting a new window from scratch at any position**. The problem requires finding the maximum sum of a contiguous subarray with all unique elements, which means we need to consider **all possible starting positions**, not just maintain one continuous window from the beginning. When negative or zero values appear, the optimal solution may exclude them entirely by starting the subarray later, but the current implementation always includes all elements from position 0 up to some point.

Alternatively, modify the existing approach to allow the window to "reset" (move `left` forward without being triggered by duplicates) when `current_sum` becomes negative or when starting fresh would yield a better result, and ensure `left` can jump to any position, not just incrementally.

FIX: Specifically, change the outer loop structure to iterate over all possible starting positions `left` from 0 to len(nums)-1, and for each starting position, use an inner loop with `right` extending from `left` onwards, maintaining unique elements in a set and tracking the maximum sum found.
