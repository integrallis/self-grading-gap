### test_canonical_example_2
**Input:** `nums = [10, 2, 3, 4, 5, 5, 4, 3, 2, 2]`, `k = 10`  
**Expected:** `4`

After sorting: `[2, 2, 2, 3, 3, 4, 4, 5, 5, 10]`

However, the problem requires finding the maximum frequency of a **specific target value `k`** (not any arbitrary value), where we can add the same value to a contiguous subarray.

This is solving a different problem: "maximum frequency of any value after increments" rather than "maximum frequency of the target value `k`".

## Root Cause

All three failures stem from the same algorithmic error: **the implementation solves a different problem**. It finds the maximum frequency achievable by making elements equal to the maximum element in a sliding window, when it should find the maximum frequency of the specific target value `k` by adding the same value to a contiguous subarray.
