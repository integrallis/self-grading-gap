## Analysis

### test_marked_indices_not_reused — expected 3, got 2

**Input:** `"azza"`

**Expected:** 3

**Trace:**
- i=0, 'a': no j < i, continue
- i=1, 'z': mirror is 'a', j=0 matches, mark j=0, score = 1-0 = 1, marked[0]=True
- i=2, 'z': marked[2]=False, mirror is 'a', j=1 is 'z' (no match), j=0 is 'a' but marked[0]=True (skip), no match found, score remains 1
- i=3, 'a': marked[3]=False, mirror is 'z', j=2 is 'z' (match), mark j=2, score = 1 + (3-2) = 2, marked[2]=True

**Problem:** When i=1 matches with j=0, the implementation only marks `marked[j] = True` but does NOT mark `marked[i] = True`. This means position i=1 is never marked. The algorithm should mark both positions in a matched pair to prevent reuse of either position.

### test_long_distance_match — expected 1, got 170

**Input:** `"abcdefghijklmnopqrstuvwxyza"`

**Expected:** 1

**Trace (partial):**
- The string has 'a' through 'z' (26 chars) followed by 'a' (position 26)
- As the loop processes each position, many characters will find their mirrors in earlier positions
- For example:
  - i=1, 'b' (mirror='y'): no 'y' before, continue
  - i=2, 'c' (mirror='x'): no 'x' before, continue
  - ...
  - i=13, 'n' (mirror='m'): 'm' is at j=12, matches, score += 1
  - i=14, 'o' (mirror='l'): 'l' is at j=11, matches, score += 3
  - ... and many more pairs in the second half of the alphabet

**Problem:** Same root cause as above. When a pair is matched, only `marked[j] = True` is set, but `marked[i]` is never set to True. This allows position i to be reused as a j in future iterations. For instance, after i=13 matches with j=12, position 13 is not marked, so when i=26 ('a', mirror='z') looks backwards, it can match with j=25 ('z') AND position 13 could potentially be matched again if it were someone's mirror. The accumulation of these incorrect matches leads to score=170 instead of 1.

## Root Cause

Both failures stem from the same bug: when a mirror pair is found at positions i and j, the implementation only marks `marked[j] = True` but fails to mark `marked[i] = True`. According to the problem specification (evident from test comments), both positions in a matched pair must be marked to prevent either from being reused.
