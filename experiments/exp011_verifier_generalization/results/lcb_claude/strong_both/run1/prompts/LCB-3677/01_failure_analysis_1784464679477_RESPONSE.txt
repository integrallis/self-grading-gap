- Trace: Starting at (0,0) with value 1, the robot can go:
  - Path (0,0)→(0,1)→(1,1): 1 + 2 + 5 = 8

## Root Cause Summary

All four failures stem from the same issue: **the implementation is treating the grid as if the robot collects coins from cells it visits, but the problem actually requires collecting from exactly `m + n - 1` cells (the path length from top-left to bottom-right).** 

Looking more carefully at the initialization: `dp[0][0][0] = coins[0][0]` suggests the starting cell's value is counted. Then in the DP transitions, when moving from (i-1,j) or (i,j-1) to (i,j), the code adds `current_value` to the previous state, which means it's adding the value at position (i,j). This is correct DP logic for path problems.

However, examining test_all_positive more carefully: the grid `[[1,2],[3,5]]` should give path (0,0)→(1,0)→(1,1) = 1+3+5=9 OR path (0,0)→(0,1)→(1,1) = 1+2+5=8. The test expects 8, which is the maximum... wait, that's the minimum of the two paths, not maximum.

Re-reading the test comments: this appears to be asking for the **maximum** coins. Let me reconsider. For `[[1,2],[3,5]]`, max path should be 1+3+5=9, but test expects 8. Unless... let me check if there's a constraint on the number of cells visited.

Actually, re-examining: in a m×n grid going from (0,0) to (m-1,n-1) moving only right/down, you visit exactly m+n-1 cells. For a 2×2 grid, that's 3 cells. Both paths visit 3 cells. So that's not the issue.

The test expects 8 not 9, so it seems like the **starting cell should NOT be counted**, only cells you move TO.
