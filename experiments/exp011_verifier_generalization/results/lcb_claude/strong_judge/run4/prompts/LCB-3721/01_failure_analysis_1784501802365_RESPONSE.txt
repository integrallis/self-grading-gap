## Root Cause Summary

**Primary issue**: In OFFLINE events, the user ID is provided as a bare number (e.g., `"0"`, `"1"`), NOT as a string with "id" prefix (e.g., `"id0"`). The code at line 14 incorrectly assumes the format is `"id<number>"` and tries to strip the first two characters with `data[0][2:]`, which leaves an empty or invalid string when the input is just a digit.

**Secondary issue** (would surface in test_mixed_mention_tokens after fixing primary): When a MESSAGE contains mixed tokens like "id0 ALL", the code attempts to parse "ALL" as an ID by doing `int("ALL"[2:])` at line 33, which would fail. The code needs to handle special tokens ("ALL", "HERE") even when they appear mixed with specific user IDs in a message.

Specifically: after splitting `ids = mentions_string.split()`, iterate through each token, and if the token is "ALL", increment all users' mention counts; if the token is "HERE", increment online users' mention counts; otherwise parse it as a user ID with `int(uid[2:])`.
