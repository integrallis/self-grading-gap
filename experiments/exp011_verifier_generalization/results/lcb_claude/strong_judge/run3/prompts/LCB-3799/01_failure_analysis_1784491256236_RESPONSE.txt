## Analysis

### test_large_array — expected 76, got 52

**Input:** `[0, 1, 2, 3, 4, 5]`  
**Expected:** 76  
**Got:** 52

**Trace:**

The implementation counts valid 3-digit even numbers by iterating over:
- `first_digit` in `{0, 1, 2, 3, 4, 5}` (skipping 0)
- `middle_digit` in `{0, 1, 2, 3, 4, 5}`
- `last_digit` in even_digits `{0, 2, 4}`

For each combination, it creates a `Counter` of `[first_digit, middle_digit, last_digit]` and checks if we have enough of each digit.

**The problem:** When `first_digit`, `middle_digit`, and `last_digit` are all distinct, the implementation counts this as **one** valid number. However, when the input contains distinct digits (each appearing exactly once), there can be multiple **permutations** of the same set of three distinct digits that form different 3-digit numbers.

For example, with digits {1, 2, 4}:
- The implementation's logic checks once: "Can I use 1, 2, 4?" → Yes → count += 1
- But there are actually **multiple distinct numbers**: 124, 142, 214, 412 (all valid 3-digit even numbers using these three digits)

The current implementation only counts **combinations** (which digits are used), not **permutations** (the distinct orderings that form different numbers).

- The current code would count combinations like {1,2,4}, {1,3,2}, {1,3,4}, etc.
- But it happens to get the right answer (12) because the test case has a balanced structure where this approach coincidentally works.

**For [0, 1, 2, 3, 4, 5]:**
- The implementation counts 52 combinations
- But many combinations represent multiple distinct permutations
- Example: {1, 2, 4} can form 4 numbers (1 in hundreds, 2 in tens OR 1 in hundreds, 4 in tens OR 2 in hundreds, 1 in tens OR 4 in hundreds, 1 in tens) = positions matter

**Root cause location:** The entire counting logic in the triple-nested loop (lines 10-17) is fundamentally flawed. It checks whether a combination of digits is *available* but only increments the count by 1, when it should count how many distinct *orderings* (permutations) of those digits form valid 3-digit even numbers.
