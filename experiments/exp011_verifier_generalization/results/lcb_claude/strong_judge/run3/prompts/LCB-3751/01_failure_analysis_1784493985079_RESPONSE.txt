## Root Cause

All six failures stem from the same fundamental misunderstanding: **the implementation treats `k` as a budget of operations to make elements equal to the maximum element in a window, but `k` is actually the target value that elements should be converted to equal**.

The correct algorithm should find the maximum frequency achievable where all elements in a subarray can equal the value `k` (not equal to each other, but specifically equal to k).

## FIX DIRECTIVES:

FIX: The entire algorithmic approach in `maxFrequency` is incorrect. The parameter `k` is the target value to achieve, not an operations budget. Rewrite the function to: (1) Count how many elements already equal k; (2) For elements less than k, they can be incremented to k; (3) For elements greater than k, they cannot be made equal to k; (4) Find the maximum count of elements that either already equal k or are less than k in any contiguous subarray, since only those can become k.

FIX: Specifically, iterate through the sorted array and for each position, count backwards (or use a sliding window) to find how many consecutive elements (all ≤ k) can be included where the element at that position is k or can become k. Elements greater than k should immediately break any such window since they cannot be decremented to k.
