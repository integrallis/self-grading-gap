## Analysis

### test_negative_total_coins — expected -1, got 0

**Input:** `[[-1, -1], [-1, -1]]`  
**Expected output:** `-1`  
**Actual output:** `0`

**Trace:**
- Grid is 2×2, all cells contain -1
- Initialization: `dp[0][0][0]` should be the coin value at start
  - `coins[0][0] = -1`, which is `< 0`
  - Line sets `dp[0][0][0] = 0` (because `coins[0][0] >= 0` is False, so else branch: `0`)
  - Line also sets `dp[0][0][1] = 0` (neutralizing the starting cell)
- This is already wrong: the starting cell value should be **collected**, not skipped
- With `dp[0][0][0] = 0` instead of `-1`, all paths that collect negative values will compute higher totals than they should
- The optimal path (0,0)→(0,1)→(1,1) with 2 neutralizations should give: -1 + 0 + 0 = -1
- But the implementation starts with 0 instead of -1, giving: 0 + 0 + 0 = 0

**Root cause:** Line `dp[0][0][0] = coins[0][0] if coins[0][0] >= 0 else 0` incorrectly treats a negative starting cell as contributing 0 coins when not neutralized. The starting cell must always contribute its value unless neutralized. The logic conflates "neutralization" with "skipping negative values."
