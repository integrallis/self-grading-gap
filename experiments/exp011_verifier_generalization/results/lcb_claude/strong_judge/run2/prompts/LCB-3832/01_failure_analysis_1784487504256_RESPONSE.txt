**Root cause**: Both failures stem from the same algorithmic error. The implementation only looks backward (at `answer[i-1]`) when computing the minimum cost for position `i`, but the problem requires looking forward as well. Each position should have access to the minimum cost among all positions at index `i` or greater. The current approach (`answer[i] = min(answer[i - 1], cost[i])`) computes a forward-propagating minimum from left to right, but the problem needs a backward-propagating minimum from right to left (the minimum of all costs from position `i` to the end).

FIX: In minCosts, replace the entire algorithm. Instead of computing `answer[i] = min(answer[i - 1], cost[i])` in a forward pass, compute the minimum cost available from position i onwards using a backward pass: start from the last position with `answer[n-1] = cost[n-1]`, then for each position `i` from `n-2` down to 0, set `answer[i] = min(cost[i], answer[i + 1])`.
