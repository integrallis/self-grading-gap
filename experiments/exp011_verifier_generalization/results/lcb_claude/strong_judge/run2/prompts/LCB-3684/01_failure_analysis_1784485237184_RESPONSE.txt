### test_wildcard_matches_many_characters
**Input:** `s = "abcdef"`, `p = "a*e"`  
**Expected:** `True` (the pattern should match "abcde" in the string)  
**What the implementation computes:**

- `star_index = 1` (index of '*')
- `prefix = "a"` (p[:1])
- `suffix = "e"` (p[2:])
- Loop range: `range(len("abcdef") - len("a") - len("e") + 1)` = `range(6 - 1 - 1 + 1)` = `range(5)` = `[0, 1, 2, 3, 4]`
- **i = 0:** `s[0:1] = "a"` equals prefix. Check if `s[1:]` = `"bcdef"` ends with `"e"`. No, it ends with `"f"`. Continue.
- **i = 1:** `s[1:2] = "b"` does not equal prefix `"a"`. Continue.
- **i = 2:** `s[2:3] = "c"` does not equal prefix `"a"`. Continue.
- **i = 3:** `s[3:4] = "d"` does not equal prefix `"a"`. Continue.
- **i = 4:** `s[4:5] = "e"` does not equal prefix `"a"`. Continue.
- Returns `False`

**Problem:** At i=0, when prefix matches at position 0, the code checks `s[i + len(prefix):]` = `s[1:]` = `"bcdef"`, which does NOT end with `"e"`. The bug is that `endswith` checks if the suffix appears at the very end of the remaining substring, but it should check if the suffix appears anywhere at or after the prefix, with the wildcard matching any characters in between.

The implementation should look for the suffix starting from position `i + len(prefix)` onward, not require it to be at the very end of `s`.

**Problem:** Same root cause as the first failure. At i=2, the prefix "c" matches, and `s[3:]` = `"abc"` contains the suffix "a" but not at the end. The `endswith` check is too restrictive.

**Root cause (both failures):** The expression `s[i + len(prefix):].endswith(suffix)` on the line with `endswith` requires the suffix to be at the very end of the string, but it should only require that the suffix appears somewhere after the prefix with at least `i + len(prefix)` positions from the start and the suffix ending at or before the end of `s`.
