### test_wildcard_matches_many_characters
- **Input:** `s = "abcdef"`, `p = "a*e"`
- **Expected:** `True` (should match "abcde" — prefix "a" at position 0, wildcard matches "bcd", suffix "e" at position 4)
- **Trace:**
  - `star_index = 1`
  - `prefix = "a"`
  - `suffix = "e"`
  - Loop runs from `i = 0` to `i = 5 - 1 - 1 + 1 = 4` (range is 0 to 4 inclusive)
  - At `i = 0`: `s[0:1] = "a"` matches prefix
    - Check `s[1:].endswith("e")` → `"bcdef".endswith("e")` → `False`
  - At `i = 1`: `s[1:2] = "b"` doesn't match prefix "a"
  - At `i = 2`: `s[2:3] = "c"` doesn't match prefix "a"
  - At `i = 3`: `s[3:4] = "d"` doesn't match prefix "a"
  - At `i = 4`: `s[4:5] = "e"` doesn't match prefix "a"
  - Returns `False`
- **Problem:** At line `if s[i + len(prefix):].endswith(suffix)`, the check is too strict. When prefix matches at position 0, `s[1:]` is "bcdef", which doesn't end with "e". However, the suffix "e" appears at position 4, which IS after the prefix at position 0. The algorithm requires that the **entire remaining string after the prefix** ends with the suffix, but it should only require that the suffix appears **somewhere** after the prefix (not necessarily at the very end of the entire string).

### test_both_prefix_and_suffix_appear_but_not_in_correct_order
- **Input:** `s = "abcabc"`, `p = "c*a"`
- **Expected:** `True` (should match "ca" — prefix "c" at position 2, wildcard matches zero characters, suffix "a" at position 3)
- **Trace:**
  - `star_index = 1`
  - `prefix = "c"`
  - `suffix = "a"`
  - Loop runs from `i = 0` to `i = 6 - 1 - 1 + 1 = 5` (range is 0 to 5 inclusive)
  - At `i = 0`: `s[0:1] = "a"` doesn't match prefix "c"
  - At `i = 1`: `s[1:2] = "b"` doesn't match prefix "c"
  - At `i = 2`: `s[2:3] = "c"` matches prefix
    - Check `s[3:].endswith("a")` → `"abc".endswith("a")` → `False`
  - At `i = 3`: `s[3:4] = "a"` doesn't match prefix "c"
  - At `i = 4`: `s[4:5] = "b"` doesn't match prefix "c"
  - At `i = 5`: `s[5:6] = "c"` matches prefix
    - Check `s[6:].endswith("a")` → `"".endswith("a")` → `False`
  - Returns `False`
- **Problem:** Same root cause as above. When prefix "c" matches at position 2, `s[3:]` is "abc", which doesn't end with "a" (it ends with "c"). But suffix "a" does appear at position 3, immediately after the prefix. The algorithm incorrectly requires the remaining string to **end** with the suffix.

**Root Cause:** Both failures have the same cause. The implementation uses `s[i + len(prefix):].endswith(suffix)`, which checks if the remainder of the string ends with the suffix. This is incorrect. The correct logic is: after finding the prefix at position `i`, find the suffix at any position `j` where `j >= i + len(prefix)`, and ensure there's room for both prefix and suffix (they can overlap with the wildcard matching zero or more characters in between).
