### Root Cause

The implementation fails tests where position values are very large (10^9) because it creates an array of size `max_position+1`, causing memory allocation failures. Additionally, it fails test_canonical_example_1 due to an off-by-one error in the sliding window logic - the initial window calculation uses `sum(coin_count[1:min(k+1, max_position+1)])` which is correct, but the sliding logic adds `coin_count[i+k-1]` when it should add `coin_count[i+k]` (the element at position `i+k` when sliding from `[i, i+k-1]` to `[i+1, i+k]`).
