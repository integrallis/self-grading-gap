**test_run_longer_than_k** — expected True, got False

- The character immediately before (if exists) is different OR we're at the start, AND
- The character immediately after (if exists) is different OR we're at the end

But the test expects True when neither position satisfies BOTH boundary conditions simultaneously.

**Re-examining the test comments**: The comment says the substring "exists at multiple positions" — this suggests that the function should return True if there exists ANY substring of k identical characters with valid boundaries, not necessarily requiring both boundaries to be valid. But wait — the implementation already does an OR across all positions.

**Re-reading test_failed_boundaries**: "hasSpecialSubstring("aaa", 2) -> False (any substring "aa" has 'a' on both sides)" — this confirms that having the same character on both sides makes it invalid.

**Deeper analysis of test_run_longer_than_k**: The test expects True for "aaaa" with k=2. Looking at positions:
- Position 0: "aa" with nothing before (valid) and 'a' after (invalid)
