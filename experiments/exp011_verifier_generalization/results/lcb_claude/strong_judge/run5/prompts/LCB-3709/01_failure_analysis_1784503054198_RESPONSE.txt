### test_run_longer_than_k — expected True, got False

**Inputs:** `s = "aaaa"`, `k = 2`

**Expected:** `True` (because substring "aa" at position 0 has no character before it and 'a' after it—but wait, the test comment says "substring 'aa' exists at multiple positions", suggesting any valid position should work)

**Trace:**
- `n = 4`, `k = 2`
- Loop runs for `i` in `range(3)` → `i = 0, 1, 2`

  - **i = 0:** substring = "aa", before_diff = True (i == 0), after_diff = False (s[2] = 'a' == 'a')
    → Condition fails
  
  - **i = 1:** substring = "aa", before_diff = False (s[0] = 'a' == 'a'), after_diff = False (s[3] = 'a' == 'a')
    → Condition fails
  
  - **i = 2:** substring = "aa", before_diff = False (s[1] = 'a' == 'a'), after_diff = True (i + k == 4 == n)
    → Condition fails

- Returns `False`

**Root cause:** The implementation requires BOTH `before_diff` and `after_diff` to be True simultaneously. However, in "aaaa", every "aa" substring either has an 'a' before it or an 'a' after it (or both). The test expects this to return True, meaning the boundary condition logic is incorrect.

Looking at the passing test `test_failed_boundaries` with input `("aaa", 2)` → `False`, we see that "aa" substrings with 'a' on both sides should fail. But in "aaaa", at position 0, "aa" has nothing before and 'a' after—the test expects this to be valid.

**Divergence point:** The `if before_diff and after_diff:` condition on line 9 is too restrictive. It should be `if before_diff or after_diff:` (at least one boundary is different).
