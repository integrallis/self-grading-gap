## Root cause

The implementation has a critical flaw: when encountering a negative value (robber), it only updates `dp[i][j][k+1]` (incrementing neutralizations) but never updates `dp[i][j][k]` (taking the penalty). This means the robot **must** neutralize every robber it encounters, which violates the constraint that only 2 neutralizations are allowed. The correct behavior should allow either neutralizing OR taking the penalty for each robber.
