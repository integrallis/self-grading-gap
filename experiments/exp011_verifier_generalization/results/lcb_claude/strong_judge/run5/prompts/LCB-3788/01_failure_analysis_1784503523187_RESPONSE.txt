The problem is that the algorithm is finding the maximum sum of a **contiguous subarray** with unique elements (a sliding window). But according to the test, when there are duplicates like `[5, 5, 3]`, we should delete duplicates and select only unique values, getting just one 5 (not 5+3=8). The algorithm doesn't match the problem specification—it's computing maximum sum of contiguous unique subarrays, not maximum sum after deleting duplicates and selecting any subset of remaining unique elements.

## Root Cause

Both failures stem from a **fundamental algorithmic misunderstanding**. The implementation treats this as a "maximum sum contiguous subarray with unique elements" problem (sliding window), but the specification requires:
1. Delete duplicate occurrences of values
2. From the remaining unique values, select any subset (possibly non-contiguous) that maximizes the sum

The correct approach: for each unique value in the array, if it's positive, include it once in the sum; if it's negative or zero, don't include it (unless all values are negative, in which case return the maximum single value).
