### Root Cause Analysis

The implementation fails because the `canAchieve` function does not correctly determine if all nodes can reach node 0. The traversal algorithm is flawed. It processes edges from a priority queue but fails to ensure that these edges connect to the component that is already reachable from node 0.

Specifically, when an edge `u -> v` (represented in reverse as `v -> u`) is processed, the code checks if node `u` is reachable (`if not reachable[u]`) and marks it as such. However, it never verifies that node `v` is *already* reachable from node 0. This means the algorithm can mark a node as "reachable" because it's part of a disconnected component, not because it has a path to node 0. This logic is akin to building a Minimum Spanning Forest rather than a Minimum Spanning Arborescence rooted at 0.

This single logical flaw causes the `canAchieve` function to incorrectly return `False` for valid maximum weights, leading the binary search to converge on the initial value of `-1`.
