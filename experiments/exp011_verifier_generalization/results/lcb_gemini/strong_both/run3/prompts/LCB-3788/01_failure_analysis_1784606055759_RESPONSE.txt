### `test_only_non_positive_numbers`

-   **Input:** `nums = [-1, -2, 0, -1, 0]`
-   **Expected:** `0`
-   **Actual:** `-1`
-   **Analysis:** The implementation uses a sliding window `[left, right]` to maintain a contiguous subarray with unique elements. It then updates `max_sum` with the sum of this entire window. This is the source of the error. The maximum sum may not come from the entire window, but from a sub-portion of it.
    -   When `right` is `2`, `nums[right]` is `0`. The window becomes `[-1, -2, 0]`, which is unique. `current_sum` is `-3`. `max_sum` (initialized to `-inf`, then `-1` from the first element) remains `-1`.
    -   The algorithm fails to consider that within the window `[-1, -2, 0]`, the subarray `[0]` has a sum of `0`, which is greater than the current `max_sum` of `-1`. The implementation never checks the sums of suffixes or other sub-portions of its valid window.

### `test_boundary_values`

-   **Input:** `nums = [-100, 100, -100, 0, 100]`
-   **Expected:** `100`
-   **Actual:** `0`
-   **Analysis:** This fails for the same root cause as the previous test.
    -   When `right` is `1`, `nums[right]` is `100`. The window is `[-100, 100]` with `current_sum = 0`. `max_sum` is updated to `0`. The algorithm does not check the suffix `[100]` which has a sum of `100`.
    -   Later, when `right` is `4`, a valid unique window is `[-100, 0, 100]` with `current_sum = 0`. `max_sum` remains `0`. The algorithm fails to check the suffix `[0, 100]`, which has a sum of `100`.

### `test_max_length_all_negative`

-   **Input:** `nums = [-100, -99, ..., -1]`
-   **Expected:** `-1`
-   **Actual:** `-100`
-   **Analysis:** This also fails due to the same fundamental flaw.
    -   As `right` increases, the array has all unique elements, so the window `[left, right]` simply expands. `left` always remains `0`.
    -   `current_sum` is first `-100`, then `-100 + -99 = -199`, and it continues to decrease.
    -   `max_sum` is set to `-100` on the first iteration and is never updated again, because `current_sum` only becomes more negative.
    -   The implementation does not check any suffixes of the expanding window. When the window is `[-100, ..., -1]`, it fails to test the suffix `[-1]`, which has the maximum possible sum of `-1`.
