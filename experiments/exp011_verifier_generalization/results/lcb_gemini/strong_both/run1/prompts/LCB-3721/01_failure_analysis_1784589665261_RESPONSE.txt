The implementation is failing one test case related to the processing order of events that occur at the same time.

`test_simultaneous_offline_and_here_message` — expected `[0, 1]`, got `[1, 1]`, because `MESSAGE` events are processed before `OFFLINE` events at the same timestamp. The test specification requires that status changes (`OFFLINE`) are resolved before messages are processed at any given timestamp. The current implementation sorts events by timestamp only. When two events have the same timestamp, their relative order is not guaranteed to be correct. In this test, the `MESSAGE` event at `t=10` is processed before the `OFFLINE` event at `t=10`, causing user 0 to be counted as "online" for the `HERE` mention, which is incorrect. The divergence happens in the main event loop, which processes a `MESSAGE` event for user 0 before their status is updated to `OFFLINE` by the subsequent event in the sorted list.

### FIX DIRECTIVES:

FIX: in `countMentions`, modify the event sorting to prioritize `OFFLINE` events over `MESSAGE` events at the same timestamp. Change `events.sort(key=lambda x: int(x[1]))` to `events.sort(key=lambda x: (int(x[1]), 0 if x[0] == 'OFFLINE' else 1))`.
