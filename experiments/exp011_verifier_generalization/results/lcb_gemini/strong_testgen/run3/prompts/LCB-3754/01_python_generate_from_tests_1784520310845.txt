Tests for the `maxDistance` function.

The problem asks for the maximum Manhattan distance from the origin at any point in a path,
given we can change at most `k` moves in the path string `s`. A key insight is that the
order of maximization can be swapped: `max_over_paths(max_over_time(dist))` is equivalent
to `max_over_time(max_over_paths(dist))`. This simplifies the problem greatly. We can iterate
through each possible path endpoint `i` (from `0` to `len(s)-1`) and, for each, calculate
the maximum possible Manhattan distance at that specific time, assuming we can use our entire
budget of `k` changes on the prefix `s[0...i]`. The overall answer is the maximum of these
values over all `i`.

For a given prefix of length `L = i + 1`, we have a budget of `c = min(k, L)` changes.
To maximize the Manhattan distance `|x| + |y|`, we need to maximize one of `x+y`, `x-y`,
`-x+y`, or `-x-y`. For each of these four "target diagonals," we can calculate the maximum
value achievable. For instance, to maximize `x+y`, we should change moves that go toward
the southwest ('S', 'W') into moves that go toward the northeast ('N', 'E'). Each such
change costs 1 and increases the `x+y` sum by 2. By calculating the maximum for all four
diagonals and taking their maximum, we find the best possible distance at time `i`. The
final answer is the maximum found across all `i`. This leads to an `O(N)` solution where
`N` is the length of `s`.
"""
