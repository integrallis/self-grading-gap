# exp009 — first evaluation pilot on rgrbench (pre-registered)

**Committed before the first API call. Purpose: feasibility + calibration of the dataset
as an evaluation instrument. A weak model builds implementations from the dataset's
requirements documents (which are derived from tests the model never sees); a machine-
authored adapter maps each candidate's API onto the oracle's names under the harness's
enforced non-cheating regime (static AST constraints + fault-injection transparency); the
package's hand-verified test suite grades the result.**

## Design (frozen)

- Instrument: `rgrbench` @ its pushed commit (recorded in plan.json);
  harness `evaluate()` unmodified.
- Model W = gpt-4o-mini (T=0.7) for BOTH candidate generation and adapter authoring.
- Packages: stratified deterministic sample, 8 per tier (first 8 alphabetically per tier
  in dataset.json) = 24 packages.
- Candidate generation prompt: the package's requirements document only (never tests,
  never reference source); output one Python module under package name `candidate`.
- Adapter authoring prompt: the candidate source + the oracle's IMPORT SURFACE only —
  mechanically extracted import statements from the oracle test file (`from X import Y`
  lines), never test bodies. Signature mismatches are expected and measured, not patched.
- One generation per package (single-shot; no retries, no feedback) — this pilot measures
  the instrument, not a system's best performance.

## Measures (frozen)

Per package: adapter static verdict; evaluation validity (transparency ≥ 0.5); per-test
outcomes; oracle pass fraction. Aggregates stratified by tier and provenance class.

- **H-C1 (calibration):** mean oracle pass fraction decreases monotonically across tiers
  (beginner > intermediate > advanced).
- **H-C2 (instrument):** ≥ 70% of packages yield a VALID evaluation (adapter statically
  clean, oracle collects, transparency above threshold). Below that, the adapter protocol
  needs revision before any study uses the dataset — that would be the finding.
- **H-C3 (open):** provenance classes do not differ in pass fraction beyond the pilot's
  resolution (descriptive only at n=24).

Failure taxonomy recorded per invalid case: static-reject / import-failure / low-transparency.

**Budget cap $10**, runner-enforced. Results in `results/` (per-package JSON + usage);
`ANALYSIS.md` generated by the analyze stage, never hand-edited.

## Amendment (2026-07-14, before any valid data)

The first run was invalidated by an environment bug in the caller, not the protocol: the
harness's pytest subprocess inherited a venv without pytest-timeout, so every evaluation
aborted at collection and was misreported as an adapter import failure. The harness now
records the pytest output tail when collection fails (diagnosability), the venv carries
pytest-timeout, and the invalidated artifacts sit in `results/quarantine-env-bug/`
($0.02 spend). Note kept honest: 6 of the 24 quarantined cases were true static rejects —
the model emitted control flow in adapters and the gate caught it — consistent with H-C2
being a real question. Full rerun from zero; design unchanged.

## Amendment 2 (2026-07-14, protocol v2 — before official-run commitment)

Refinements from the first valid run's failure taxonomy, applied before any paper-official
runs: (a) harness protocol v2 (dataset repo): candidate-execution check (passing tests must
execute candidate code, coverage-measured) plus coverage-guided fault injection (faults
target executed lines only, ending false low-transparency verdicts on weak candidates with
dead code) and parametrized-test-id parsing; (b) runner: one adapter repair round on static
violations (form feedback only — no grading information flows), and the mechanically
extracted surface now includes observed call shapes (arities) alongside imports. The
protocol-v1 run is quarantined (results/quarantine-protocol-v1/, $0.03); design and
hypotheses unchanged; rerun from zero.

## Amendment 3 (2026-07-14, protocol v3 — frontier adapter author)

The v2 taxonomy isolated the last validity blocker as adapter authorship: the weak model
writes reimplementations (If/BinOp) instead of mappings on complex packages, and one repair
round does not correct it. Adapters are protocol plumbing, not the system under test, so
the adapter author becomes gpt-5.6-terra (temperature 1.0, provider constraint) while the
CANDIDATE remains gpt-4o-mini from requirements alone — the measured system is unchanged.
Protocol-v2 results quarantined (results/quarantine-protocol-v2/, $0.05); hypotheses
unchanged; rerun from zero.

## Amendment 4 (2026-07-15, protocol v3.1 — screened fault injection)

Transparency's remaining noise source was behaviorally-neutral injected faults counting
against honest adapters (v3: anagram_detector rejected at 0.43 with pass 0.95). Harness
v3.1 screens every fault at the candidate boundary (per-test call/return traces beneath
the adapter): neutral faults are discarded with replacement sampling, transparency becomes
detected / behavior-changing, no-signal cases carry a note instead of an accusation, and
partial-bypass adapters (execute-but-ignore) are now caught by construction. Protocol-v3
results quarantined (results/quarantine-protocol-v3/, $0.40); design and hypotheses
unchanged; rerun from zero. This is the freeze candidate for the official runs.
