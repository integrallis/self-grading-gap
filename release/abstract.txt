Self-testing code agents author tests, generate implementations, and use model reviewers and test execution to decide when they have succeeded. We measure the verification gap: claimed successes rejected by held-out benchmark tests. In an instrumented test-first pipeline, the all-weak control's conditional gap is 18.5% on a selected HumanEval subset and 28.9% on a LiveCodeBench window after the generator's reported training cutoff. Replacing the test author, judge, or both with one of three frontier verifiers leaves residual false accepts in every condition; no false-accept contrast meets the pre-specified effect-size and significance criteria as implemented by the original analysis. This does not establish equivalence: some point estimates decrease substantially. On LiveCodeBench, the primary frontier judge increases oracle passes and eliminates observed false rejects, with telemetry consistent with a feedback benefit. On RGRBench's 89 Python packages, the control's conditional gap is 41.5% and the strong judge's is 42.0%, but the strong judge also rejects more test suites before code generation and reduces correct output. Higher gap rates are associated with harder packages and additional attempts; these are observational comparisons. Oracle disagreement includes both implementation errors and requirements--oracle mismatches, so it is not itself proof of a violated visible requirement. We release the instrument and retained results to support independent evaluation of pipeline verdicts, with explicit limitations on causal interpretation, oracle fidelity, and provenance.
